# Predictive Query Optimization

Приложение для анализа и проверки оптимизаций SQL в PostgreSQL. Оценивает
время выполнения по структуре запроса и плану, предлагает индексные кандидаты
и варианты SQL, отдельно проверяет корректность и измеренный эффект.

## Возможности

- быстрый прогноз XGBoost через `EXPLAIN` без выполнения анализируемого SELECT;
- проверка индексов с фактическими замерами и откатом пробных изменений;
- автоматические правила переписывания и сравнение с ручным вариантом SQL;
- анализ транзакций, общие индексы и проверка поддерживаемых сценариев на копиях;
- профили локальных и удалённых PostgreSQL, несколько схем, отдельная служебная
  история и экспорт результатов.

Предварительная оценка не означает подтверждённое ускорение. Приложение может
отклонить вариант из-за несовпадения результатов, замедления, нестабильных замеров
или неподдерживаемой конструкции. Фактические проверки выполняют SQL и требуют
ресурсов БД; для них используйте тестовую копию.

## Запуск из исходников

Нужны Python 3.11+, доступный PostgreSQL и зависимости из
[pyproject.toml](pyproject.toml). Готовый установщик предназначен для Windows
10/11 x64. Команды ниже выполняются в PowerShell из корня репозитория:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[desktop]"
.\.venv\Scripts\python.exe -m pqo.desktop
```

Существующий сервер задаётся в настройках приложения. Для локального стенда
с демонстрационными данными можно запустить Docker Compose:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
docker compose up -d --wait
```

По умолчанию стенд доступен на `localhost:55432`, БД и роль —
`query_optimizer`. Начальные SQL выполняются при создании нового Docker volume;
обычный перезапуск контейнера не применяет миграции к существующим данным.

В настройках выберите исследуемую БД, загрузите схемы и отметьте нужные.
Для истории отдельно настройте служебную БД, например `pqo_service`, и подготовьте
её схему через соответствующие кнопки. Пароли профилей не сохраняются между
запусками. Подробности — в [руководстве по подключению](docs/connections.md).

## Использование

1. Вставьте `SELECT` или `WITH` на вкладке «Анализ» и получите быстрый прогноз.
2. При необходимости отдельно запустите глубокую проверку индексов или SQL.
3. Сравните результаты и измеренный выигрыш. Изменения применяются отдельным
   действием; неподтверждённый вариант применить нельзя.

Вкладка «Транзакции» работает по [собственному протоколу](docs/transactions.md):
получение планов не выполняет команды, а запись допускается только в ограниченных
сценариях на одноразовых копиях. «Обучение» и «Эксперименты» доступны в расширенном
режиме. SQL-примеры находятся в [examples](examples); выбирайте их под схемы
подключённой базы.

## Структура репозитория

| Каталог | Назначение |
| --- | --- |
| `src/pqo` | анализ SQL, модели, проверки и интерфейс PyQt6 |
| `database` | миграции, схемы и начальные данные |
| `dataset` | измерения и опыт индексных действий |
| `models` | веса, метрики и результаты контроля |
| `examples` | SQL и транзакции для проверки |
| `scripts` | сборка, резервное копирование и воспроизводимые проверки |
| `tests` | модульные и интеграционные тесты |

Параметры команд доступны через `--help`. Подключения CLI читаются из переменных
окружения; файл `.env` используется Docker Compose и не загружается Python-кодом
автоматически.
