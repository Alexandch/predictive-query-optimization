# Ограниченные сочетания переписываний

Автоматическая проверка раньше предлагала каждое правило отдельно. Теперь после
одиночных вариантов генератор добавляет до двух уникальных сочетаний из двух
разных правил. Например: убрать внутренний ORDER BY без LIMIT и заменить
коррелированный COUNT(*) > 0 на EXISTS.

Одиночные варианты сохраняют приоритет и не заменяются сочетаниями. Копирование
AST изолирует преобразования друг от друга; одинаковый итоговый текст
отбрасывается, в том числе при разных порядках применения правил. Глубина
ограничена двумя правилами, один и тот же приём не применяется повторно.
Параметр API генератора `max_combined_candidates` допускает 0–4, по умолчанию 2.
Это ограниченный поиск, не полный перебор всех возможных переписываний.

Каждый составной вариант независимо проходит существующий протокол:

- read-only REPEATABLE READ-транзакция;
- сравнение мультимножеств через EXCEPT ALL в обе стороны;
- фактические замеры исходного и нового SQL;
- проверка абсолютного и относительного выигрыша.

Совпадение результатов на снимке не доказывает эквивалентность для любых данных
и не проверяет порядок строк. Сочетания не обходят ограничения отдельных правил,
не применяются автоматически и не гарантируют ускорение. Новые проверки могут
увеличить длительность кнопки проверки SQL, но не быстрого ML-прогноза.

В интерфейсе название начинается с «Сочетание», в локальном журнале сохраняется
идентификатор `combined:<первое правило>+<второе правило>`. Эти записи не
добавляются в обучение и не меняют действующие модели автоматически.
Существующие пакетные эксперименты и их контрольные проверки явно используют
`max_combined_candidates=0`: их зафиксированный набор кандидатов не расширяется
задним числом. Для исследования сочетаний нужен отдельный эксперимент.

Пример для ручной проверки: `examples/retail-combined-rewrite.sql`. Вставьте его
в левый редактор и нажмите «Проверить безопасное переписывание SQL». Если исходный
SQL короче текущего порога времени, проверка корректно остановится до кандидатов.

После проверки над правым редактором появляется список всех проверенных
вариантов, включая одиночные и составные. Выбор показывает SQL, статус, медианы,
пороги выигрыша и текстовые изменения. Переключение не выполняет запрос и не
меняет левый редактор. Для отклонённого варианта применение недоступно; его можно
отредактировать и отдельно проверить. Изменение исходного текста сбрасывает
список результатов. Во время фоновой операции выбор заблокирован.

Интеграционный тест на TEMP-таблицах проверяет дубликаты и NULL, выполняет весь
протокол измерения и подтверждает отказ при недостигнутом пороге выигрыша.
