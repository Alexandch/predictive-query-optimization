# Резервное копирование и восстановление

Windows-скрипты работают с PostgreSQL из локального Docker Compose. Один снимок
содержит одну БД, локальные артефакты приложения/проекта, настройки Windows при
их наличии и manifest с размерами и SHA-256. `.env` не копируется.

Имя БД задаётся `POSTGRES_DB`, роль — `POSTGRES_USER`; по умолчанию оба значения
`query_optimizer`. Профили подключений GUI эти скрипты не читают. При отдельной
служебной БД `pqo_service` её нужно сохранять отдельно. Для внешнего сервера
используйте его штатный процесс резервного копирования.

## Создание снимка

Docker Desktop и контейнер должны работать:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup_windows.ps1
```

Пример отдельной копии служебной БД:

```powershell
$env:POSTGRES_DB = "pqo_service"
powershell -ExecutionPolicy Bypass -File scripts\backup_windows.ps1 -BackupRoot "E:\PQO Backups\service"
```

Для разных БД используйте разные каталоги хранилища. По умолчанию путь выбирается
из `PQO_BACKUP_ROOT`, каталога OneDrive либо соседнего с проектом `PQO Backups`.
Незавершённый снимок имеет имя `.partial-*` и не участвует в восстановлении.
Окончательное имя появляется после успеха; результат фонового запуска записывается
в `last-backup-status.json`.

По умолчанию остаётся минимум семь снимков, более старые удаляются после 30 дней.
Параметры — `-MinimumCopies` и `-RetentionDays`. Незавершённые собственные каталоги
старше суток очищаются отдельно.

## Плановый запуск

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_backup_task.ps1 -DailyAt "20:00"
```

Задача запускается от текущего пользователя и требует Docker Engine.
По умолчанию она сохраняет `query_optimizer`. Для другого имени БД нужно настроить
окружение самой задачи: переменная, заданная только в открытом PowerShell, не
становится постоянной настройкой планировщика. Удаление задачи — параметр `-Remove`.

## Восстановление

```powershell
powershell -ExecutionPolicy Bypass -File scripts\restore_windows.ps1
```

По умолчанию последний завершённый снимок восстанавливается в отдельную БД
`query_optimizer_restored`. `-Snapshot` выбирает конкретный снимок,
`-BackupRoot` — хранилище, `-DatabaseName` — имя назначения.

Перед восстановлением проверяются manifest и SHA-256. Существующая БД не
заменяется без `-ReplaceDatabase`. `-RestoreArtifacts` и `-RestoreSettings`
отдельно включают восстановление файлов и настроек. Артефакты объединяются:
одноимённые файлы заменяются, остальные сохраняются.
Снимки не шифруются; учитывайте содержимое SQL-журналов и локальных результатов.
