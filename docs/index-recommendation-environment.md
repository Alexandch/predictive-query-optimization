# Среда индексных рекомендаций

## Назначение

Среда является границей между будущим DQN-агентом и PostgreSQL. Агент выбирает
номер из конечного списка типизированных действий и не получает возможности
выполнять произвольный DDL.

В одношаговом режиме поддерживаются действия:

- ничего не делать (`NOOP`);
- создать одноколоночный индекс;
- создать составной индекс максимум по трём колонкам;
- добавить максимум три колонки в `INCLUDE`.

Кандидаты строятся по колонкам условий `WHERE`, связей `JOIN`, сортировки и
выходного списка. По умолчанию разрешена только схема `aviation`. Имена схем,
таблиц и колонок проходят отдельную проверку и передаются PostgreSQL как
идентификаторы, а не как фрагменты SQL.

## Безопасность эксперимента

Для одного действия среда:

1. проверяет, что получен единственный `SELECT` или `WITH`;
2. проверяет наличие целевой таблицы в запросе и принадлежность схемы белому
   списку;
3. берёт транзакционную advisory-блокировку, чтобы эксперименты не пересекались;
4. измеряет исходный план через `EXPLAIN ANALYZE`;
5. создаёт временный индекс после точки сохранения;
6. повторяет измерения с индексом;
7. откатывается к точке сохранения и снова измеряет исходное состояние;
8. в любом случае откатывает всю транзакцию.

Ограничение `statement_timeout` не позволяет одному запросу бесконечно занимать
среду. `CREATE INDEX CONCURRENTLY` намеренно не используется, поскольку он не
может выполняться внутри необходимой откатываемой транзакции.

## Награда

Базовое и новое время вычисляются как медианы повторов. Нормированное улучшение:

```text
improvement = (baseline_ms - candidate_ms) / max(baseline_ms, 0.001)
```

Награда уменьшает улучшение на штраф за сложность:

```text
reward = improvement - 0.01 * key_columns - 0.005 * include_columns
```

Поэтому агенту невыгодно рекомендовать широкий индекс при незначительном
ускорении. Для `NOOP` награда равна нулю.

## Ручная проверка

Вывести допустимые действия:

```powershell
.\.venv\Scripts\pqo-index.exe "SELECT flight_id FROM aviation.flights WHERE departure_airport = 'MSQ'"
```

Безопасно оценить действие с номером 1:

```powershell
.\.venv\Scripts\pqo-index.exe --action-index 1 --repetitions 3 "SELECT flight_id FROM aviation.flights WHERE departure_airport = 'MSQ'"
```

Реализованный DQN использует признаки запроса, плана и статистики отношений как
состояние, список `IndexAction` как переменное пространство действий, а поле
`reward` как сигнал обучения. Вектор действия дополнительно показывает, какие
ключи индекса участвуют в `WHERE`, `JOIN`, `ORDER BY` и выходном списке текущего
SQL. Loss объединяет численную регрессию reward и попарное ранжирование действий
одного запроса. Эта постановка остаётся одношаговой для совместимости основной
модели. Отдельная среда `generic-v4-sequential`, описанная в
`sequential-index-environment.md`, уже поддерживает несколько индексов, `STOP`
и бюджет хранения.
