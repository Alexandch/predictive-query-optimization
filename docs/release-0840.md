# Выпуск 0.8.40 — отдельная служебная БД и профили источников

## Что изменилось

- В GUI отдельно настраиваются исследуемая PostgreSQL и служебная история;
  профили источников выбираются в настройках и верхнем списке «БД».
- Профиль содержит имя, сервер/порт/БД/роль, схемы и SSL/CA. Пароля в нём нет;
  пароли живут только в памяти текущего сеанса.
- Схемы загружаются чтением каталогов и выбираются флажками. Можно указать
  несколько; единственная `university` была настройкой текущей БД, не ограничением
  всей системы. В учебной `query_optimizer` другие предметные схемы.
- Служебные объекты не устанавливаются при анализе источника. Есть отдельные
  подтверждаемые действия создания пустой служебной БД и подготовки `pqo`.
- История и решения по рекомендациям используют служебное соединение;
  `query_run.target_context` хранит источник без пароля. Экспорт сохраняет этот
  контекст. Старые строки без контекста не получают выдуманное имя БД.
- Ошибка сохранения не стирает готовый прогноз/глубокий результат и не приводит
  к записи на источник. Смена источника сбрасывает старые ID и подтверждённые
  планы; переключение блокируется во время фоновой работы.
- Веса модели и возможность отката не менялись.

## Проверено 10.11.2026

Полный набор с включёнными лабораторными PostgreSQL-проверками: **679 passed**.
Отдельный набор маршрутизации создаёт две новые источниковые БД без `pqo` и
служебную БД: запись и источник истории, отказ сервиса без потери прогноза,
идемпотентная подготовка, реальная индексная проба с откатом и отказ повторного
использования ID из другой БД. Создание служебной БД проверено штатной функцией;
временные БД удалены с проверкой идентичности.

В установленном EXE проверяются запуск, пять асинхронных прогнозов, запись в
отдельную историю, эквивалентное/неэквивалентное переписывание, оценочные планы
транзакции и SELECT-замена в полной смешанной транзакции на одноразовых копиях.
Сверка 14 модулей подтверждает соответствие собранного кода исходникам.
Протоколы: `artifacts/release-0840/` (тесты, установка, smokes, проверка сборки).

Локальная `pqo_service` подготовлена отдельно от прежних БД; старую историю не
удаляли и автоматически не переносили. Проверки установленного сохранения
добавляют демонстрационную запись в новую служебную историю.

Произвольный внешний PostgreSQL поддержан параметрами подключения и SSL,
но реальный облачный сервер без пользовательских реквизитов не проверялся.
Права, сеть, сертификаты, поддерживаемые имена схем и SQL по-прежнему имеют
значение; это не универсальная оптимизация всех SQL/всех СУБД и не разрешение
выполнять DML на production. [Инструкция подключения](connections.md).

Вывод stderr PyInstaller при сборке через вложенный Windows PowerShell был
помечен оболочкой как `NativeCommandError`; сам PyInstaller завершил сборку,
Inno Setup сообщил `Successful compile`. Готовые EXE/установщик дополнительно
проверены установкой и запуском, а не только кодом возврата оболочки.
