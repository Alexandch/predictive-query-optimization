# Пакетный сбор пар SQL

Модуль `pqo.rewrite_batch` — отдельный инструмент из исходников. Он собирает
измерения для будущего обучения, но не обучает и не активирует модель.
Новых кнопок в установленном приложении на этом этапе нет.

## Откуда берутся запросы

Каталоги PostgreSQL дают реальные одностолбцовые внешние ключи целочисленного
типа. Из выбранных схем берутся до четырёх разных дочерних таблиц, с приоритетом
более крупных по статистике планировщика. Генератор строит семь шаблонов:

1. Проверка положительного COUNT → EXISTS.
2. Нулевой COUNT → NOT EXISTS.
3. Равенства OR → IN.
4. Границы диапазона → BETWEEN.
5. Удаление внутреннего ORDER BY перед внешней группировкой.
6. Перенос неагрегатного условия HAVING в WHERE.
7. NOT MATERIALIZED для повторно используемого CTE.

Это специально построенные исследовательские запросы, не репрезентативная
выборка всей пользовательской нагрузки. Они могут быть быстрыми или пустыми
при выбранных диапазонах ключей. EXISTS-примеры ограничивают число родительских
строк восемью; другие шаблоны используют диапазон ключей 1–256.
Фильтрация и LIMIT не гарантируют малого числа прочитанных страниц.

## Безопасность и бюджет

Исследуемые SQL проходят проверку SELECT/WITH и разрешённых схем. Выполнение —
в read-only REPEATABLE READ-транзакциях существующего механизма переписываний,
без CREATE INDEX, UPDATE, DELETE и постоянного изменения данных.
Каталоги тоже читаются в read-only-транзакции.

По умолчанию statement timeout — 1500 мс, максимум 28 проверок за один сеанс,
бюджет — 180 секунд. **Бюджет проверяется между случаями**, поэтому уже начатая
проверка может завершиться позже него; это не жёсткий таймер всего пакета.
Каждый отдельный SQL ограничен своим серверным тайм-аутом. Прогревы, проверка
равенства и парные прогоны выполняют несколько SQL на один случай.
Приложение и БД могут ощущать дополнительную нагрузку: запускайте сбор на
учебной/тестовой БД, не параллельно с оценкой пользовательского времени.

Три парных замера с чередованием порядка и по одному прогреву дают медианы.
Порог исходного времени равен нулю, чтобы не отбрасывать быстрые отрицательные
примеры; рекомендация принимается при выигрыше не менее 2 мс и 5%.
Значение `accepted` не используется как признак модели.

## Запуск

Сначала можно посмотреть пакет: команда обращается только к каталогам,
не выполняя генерируемые SQL. Путь вывода должен быть новым.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pqo.rewrite_batch --output artifacts/rewrite-batches/preview-new
```

Сбор по умолчанию охватывает `aviation`, `retail`, `logistics`; флаг
`--schema` можно указать несколько раз. Настройки подключения берутся из
окружения проекта, пароль не записывается в состояние пакета.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pqo.rewrite_batch --output artifacts/rewrite-batches/batch-new --execute --max-cases 28 --budget-seconds 90
```

Продолжение использует сохранённый список SQL, а не заново обнаруженные таблицы:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pqo.rewrite_batch --output artifacts/rewrite-batches/batch-new --execute --resume --max-cases 35 --budget-seconds 90
```

Изменение подключения, числа повторений, тайм-аута или содержимого списка
случаев вызывает отказ от продолжения. Завершённые и ошибочные случаи повторно
не выполняются; незавершённый случай после прерывания запускается с новой
записью журнала, прежняя неполная запись сохраняется. Блокировка файла не
позволяет двум сборщикам одновременно обновлять один пакет и освобождается
операционной системой после закрытия процесса.

## Результаты и разделение данных

Каталог пакета содержит:

- `batch.json`: SQL, протокол, статусы, идентификаторы и ошибки;
- `journal/run-*.json`: полные планы и измерения каждого опыта;
- `split.json`: ID development/control, назначенные до измерений;
- `.session.lock`: служебный файл блокировки, не признак зависшего процесса.

Принадлежность development/control определяется стабильным хэшем связи
таблиц (примерно 75/25). Все правила и варианты литералов одной связи остаются
в одной группе; последующий аудит дополнительно соединяет совпадающие формы SQL.
Контрольные записи защищены от назначения в development. Не выбирайте
разделение заново после просмотра выигрышей.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pqo.rewrite_learning --directory artifacts/rewrite-batches/batch-new/journal --manifest artifacts/rewrite-batches/batch-new/split.json --report artifacts/rewrite-batches/batch-new/audit.json
```

Состояние и журнал сохраняются атомарно. SQL и планы могут содержать
чувствительные значения; этот каталог не шифруется. Пакеты внутри `artifacts`
входят в предусмотренное проектом резервное копирование, но отдельный полный
backup пользовательской БД этим запуском не создаётся. В ZIP не включаются
временные `.batch-*.tmp` и служебные `.session.lock`, чтобы блокировка работающего
сборщика не мешала архивированию. Целые JSON сохраняются.

## Выполненный эксперимент 23.10.2026

Каталог `artifacts/rewrite-batches/collection-20261023`:

- 63 проверки: по 9 на каждое из семи правил, схемы aviation/retail/logistics;
- 63 совпадения мультимножеств и 63 полных набора парных замеров;
- 22 варианта прошли пороги выигрыша, 25 показали замедление;
- 42 строки development и 21 control, но только 6 и 3 независимые группы;
- первый сеанс 28 проверок, затем продолжение ещё 35 без повторения первых.

Итоговый аудит — `audit-complete.json`. Это локальные результаты данного запуска,
не гарантия такого же выигрыша на другой БД или при другом состоянии кэша.
Модель не обучалась: минимум 30 development- и 10 control-семейств не достигнут.
Для дальнейшего развития нужны новые **структуры** SQL и бизнес-сценарии,
а не повторные запуски этих же 63 шаблонов с другими числами.
