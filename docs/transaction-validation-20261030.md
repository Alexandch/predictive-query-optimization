# Проверка этапа транзакций: 30.10.2026, версия 0.8.26

## Что реализовано

Отдельная вкладка «Транзакции»: локальный разбор одного BEGIN … COMMIT/ROLLBACK,
порядок команд, отношения, запись/предупреждения и явный запрос оценочных планов
SELECT/INSERT/UPDATE/DELETE через EXPLAIN без ANALYZE. Подробные границы этапа
описаны в [дорожной карте](transaction-roadmap.md).

Фактическое последовательное выполнение, ML-прогноз общего времени,
общий подбор индексов и применение переписываний транзакции **не реализованы**.
Отсутствие ошибки разбора или наличие плана не означает разрешения на выполнение.

## Проверки

Полный набор: `python -B -m unittest discover -s tests -q` — 438 тестов,
396 пройдены, 42 интеграционных проверки пропущены по настройкам запуска.
Отдельный запуск `PQO_UNIVERSITY_TESTS=1` для `test_transaction_planning.py`:
10 проверок пройдены, включая две реальные проверки PostgreSQL.

Проверены:

- запрет отправки исходных BEGIN/COMMIT/DML и отсутствие ANALYZE;
- READ ONLY/REPEATABLE READ и обязательный откат контекста/каждого savepoint;
- блокирование DDL/SET, неизвестных функций, блокировок строк, SELECT INTO,
  неразрешённых схем и неподставленных параметров;
- области видимости CTE: одноимённый CTE во вложенном запросе не скрывает
  постороннюю неквалифицированную таблицу;
- продолжение после ошибки отдельной команды, тайм-ауты и общий бюджет;
- отмена, в том числе при реальном ожидании блокировки тестовой таблицы;
- блокировка конфликтующих кнопок, доставка ответа фонового потока в GUI,
  сброс планов при смене текста/подключения и игнорирование устаревшего ответа.

На `pqo_university_unseen` получены планы SELECT, UPDATE, INSERT и DELETE.
INSERT намеренно выбирает уже существующий PK: план получен, нарушения
уникальности нет, поскольку INSERT не исполнялся. Строка студента 17001
до/после полностью совпадает. План отсутствующей таблицы отмечен ошибкой,
последующий SELECT продолжает планироваться. Тест блокировки использует только
эту тестовую БД, NOWAIT и принудительный откат.

## Сборка и установка

Полная Windows-сборка выполнена `scripts/build_windows.ps1 -SkipDependencyInstall`.
Smoke-проверка ресурсов/GUI/моделей — exit 0. Готовый EXE прошёл отдельный
transaction smoke (три команды примера) и быстрый ML-анализ университетского
SELECT. На холодном старте под нагрузкой сборки быстрый анализ занял около
4,8 с; ускорение холодной загрузки моделей этим этапом не заявляется.

Установщик 0.8.26 завершился с exit 0, в реестре зарегистрирована 0.8.26.
SHA-256 установленного EXE совпадает со сборкой:

`15124737D1E63D0F55E996390AB397A25C6FBDC9033CD781A95922144E097C18`

SHA-256 установщика:

`4E6B6FD0513DCF15E6A692C7663387F57FCB1796035C3685C144FBF010C3E588`

Уже установленный EXE дополнительно прошёл `--smoke-test`,
`--transaction-smoke-test` и `--rewrite-smoke-test`, все exit 0. Последняя
проверка подтверждает сравнение двух редакторов, эквивалентность, обнаружение
различий дубликатов и сохранение исходного SQL.

Параметры подключения, выбранные модели и пороги до/после установки совпадают.
Пароль в снимки не включён. Проверки запуска изолированы через
`PQO_APP_DATA_ROOT`; рабочие история/калибровка не пополнялись.
