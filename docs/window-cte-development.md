# Развитие XGBoost: CTE, окна и DISTINCT-агрегации

Дата: 22.10.2026. Версия приложения: 0.8.18.

## Цель и протокол

Улучшить первый прогноз ранее не измеренного SQL, не подменяя прогноз
сохранённым временем того же запроса. Во всех сравнениях ниже калибровка
отключена. Запечатанные logistics- и CH-контроли не использовались для обучения,
выбора или итоговой оценки кандидата.

До сбора измерений зафиксированы 32 новых SQL из восьми семейств aviation/retail:
16 обучающих, 8 проверочных для выбора кандидата и 8 итоговых из двух отдельных
семейств. Каждый запрос имеет один прогрев и три измерения, цель — медиана.
Новые обучающие измерения объединены с исходным набором. В итоговом обучении
13 808 измерений и 6 490 уникальных SQL. Итоговая часть не включена в обучение.

Сравнивались прежние веса, переобучение с прежними признаками (абляция) и
`sql-v2`. Кандидат выбран по MAE проверочной части; после выбора итоговая часть
оценена один раз. Протокол и результаты сохраняются в
`artifacts/window-cte-development/`; эти локальные экспериментальные данные
не входят в git.

## Признаки и совместимость

Добавлены 11 признаков: количество CTE, материализованных CTE, ссылок на CTE,
оконных функций, оконных агрегатов, ранжирующих окон, ключей PARTITION BY,
ключей оконной сортировки, DISTINCT-агрегатов, FILTER и ключей GROUP BY.
Ранжирование не считается оконной агрегацией. Старый контракт признаков DQN
не изменён. Старые XGBoost-артефакты по-прежнему читаются.

Для старых CSV недостающие новые признаки восстанавливаются из SQL. Оценочные
поля плана не заменяются выдуманными значениями, исходные CSV не переписываются.

## Результаты без калибровки

| Проверка | Прежние веса, MAE мс | Новые веса, MAE мс |
| --- | ---: | ---: |
| Проверочная часть, 8 SQL | 322,06 | 193,93 |
| Итоговая часть, 8 SQL | 371,60 | 118,41 |
| Ранее известные данные, 500 SQL | 11,59 | 12,07 |

Абляция со старыми признаками получила MAE 200,44 мс на проверочной части:
часть улучшения объясняется новыми обучающими примерами, а не только признаками.
На итоговой части median Q-error снизилась с 2,253 до 1,273; доля прогнозов
с ошибкой не более 20% выросла с 0% до 50%. Итоговая MAE уменьшилась на 68,1%.
Выборка из 500 ранее известных SQL не является независимым контролем;
на ней есть небольшой регресс MAE примерно на 4,2%.

Кандидат прошёл существующее внутреннее правило замены:
parameter MAE 14,18 → 13,75 мс, R² 0,9701 → 0,9778;
unseen-template MAE 47,75 → 34,58 мс, R² 0,7761 → 0,8846.
Эти внутренние разбиения изменились вместе с набором, поэтому строгое
сравнение выполняется по общей внешней итоговой части, а не по ним.

Запрос пользователя сохранён в `examples/retail-window-ranking.sql` и не
добавлялся в обучение. Отдельная диагностика: прежний прогноз 1779,01 мс,
новый 678,99 мс; локальная медиана пяти запусков после прогрева — 913,18 мс.
Это не точное предсказание: ошибка нового прогноза около 25,6%. Замеры на
другой нагрузке или состоянии кэша могут отличаться. Холодная загрузка старой
модели и тёплая загрузка новой не сравниваются как доказательство ускорения.

## Калибровка и интерфейс

Оценка по точному SQL из профиля подписывается как оценка по предыдущим
измерениям этого SQL. Она не доказывает обобщающую способность ML.
Быстрый режим по-прежнему не выполняет пользовательский запрос.

Профили привязаны к хэшу весов, поэтому прежние профили не подмешиваются к
новой модели; их файлы сохранены. Проверка общей калибровки по трём разбиениям
старой production-нагрузки не прошла прежний порог стабильности. Порог не
понижался, веса по этим результатам не подбирались. Нельзя обещать, что общая
калибровка обязательно улучшит каждый новый запрос.

## Развёртывание и ограничения

Основные веса: `models/xgboost/xgboost_query_time.joblib`.
SHA-256: `2543cde0e5084621951bcff9d77ea4e2a1f33f70f994cce1af8dddd2aea08080`.
Прежняя модель сохранена в `models/xgboost/previous/`; полная резервная копия
до замены — `artifacts/model-archive/before-sql-v2-20261022-121636/xgboost/`.
Поле `primary_replaced: false` в экспериментальном `report.json` отражает
состояние до отдельного шага продвижения модели, а не итог развёртывания.

Скрипт воспроизведения: `scripts/window_cte_experiment.py`. Повторный запуск
после замены основной модели сравнит уже с другими исходными весами;
для воспроизведения этого сравнения нужно использовать сохранённый baseline.

```powershell
.\.venv\Scripts\python.exe scripts/window_cte_experiment.py --reuse-measurements --baseline models/xgboost/previous/xgboost_query_time.joblib --output artifacts/window-cte-development
```

Команда повторно обучает кандидатов и перезаписывает экспериментальный отчёт,
но не заменяет основные веса. Требуется сохранённый файл `measurements.csv`.

Восемь итоговых запросов недостаточны для заявления о точности на произвольной
БД. Следующий исследовательский шаг — более широкий заранее отделённый набор
семейств и масштабов данных, включая различную нагрузку и память. Нельзя
оценивать модель на запечатанном контроле, затем подбирать по нему веса и
продолжать называть его независимым.
