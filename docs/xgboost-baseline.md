# Разработка модели XGBoost

## Итоговый эксперимент

- исходных измерений: 2 400;
- строк после медианной агрегации повторов: 1 746;
- структурных шаблонов: 24;
- предметных таблиц: 8;
- целевая переменная: `actual_total_time_ms`;
- одинаковые SQL-тексты никогда не разделяются между train и test;
- гиперпараметры подбираются только внутри обучающей части;
- итоговая модель после оценки обучается на всех доступных данных.

Счётчики фактически прочитанных буферов и целевое время исключены из входа
модели. Прогноз использует `EXPLAIN (FORMAT JSON)` и не выполняет SQL-запрос.

## История улучшений

| Версия | Данные и метод | R² | MAE, мс | RMSE, мс |
|---|---|---:|---:|---:|
| v1 | 8 шаблонов, 1 000 измерений | 0,9540 | 5,55 | 16,15 |
| v2 | 24 шаблона, 2 400 измерений | 0,9710 | 2,92 | 7,45 |
| v4 | расширенные признаки и настройка | 0,9738 | 2,77 | 7,08 |
| v5 | настройка и медианная агрегация | **0,9858** | **2,44** | **5,06** |
| v6 | обучение на исходных миллисекундах | 0,9848 | 2,59 | 5,23 |

Лучшей для основной задачи выбрана версия v5. Улучшение относительно первого
бейзлайна составляет 0,0318 по R² и 3,11 мс по MAE.

## Параметры лучшей модели

- `n_estimators`: 500;
- `max_depth`: 3;
- `learning_rate`: 0,04;
- `min_child_weight`: 3;
- `subsample`: 0,70;
- `colsample_bytree`: 0,85;
- преобразование целевой переменной: `log1p`.

Средняя MAE во внутренней пятикратной групповой проверке составила 2,58 мс.
На отдельном holdout получены следующие результаты:

- R²: 0,9858;
- MAE: 2,44 мс;
- медианная абсолютная ошибка: 0,99 мс;
- RMSE: 5,06 мс;
- доля прогнозов с ошибкой до 20%: 82,29%.

## Стресс-тест новых шаблонов

Если из обучения полностью удалить шесть структурных типов запросов, версия v5
получает R² 0,773. Версия с обучением на исходных миллисекундах получает R²
0,870. Это отдельная задача экстраполяции: XGBoost надёжнее прогнозирует новые
параметры известных классов запросов, чем полностью неизвестные структуры.

Стресс-тест не используется для выбора основной модели, но сохраняется как
честно зафиксированное ограничение и направление дальнейшего расширения
датасета.

## Интеграция с десктопным приложением

Функция `predict_sql_query` является независимым Python API. Она получает SQL,
запрашивает оценочный план PostgreSQL и возвращает прогноз вместе с основными
характеристиками плана. Обработчик PyQt сможет вызывать эту функцию без импорта
кода обучения и без выполнения запроса пользователя.
