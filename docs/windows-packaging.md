# Сборка и установка в Windows

Проект собирается в автономное 64-битное Windows-приложение с помощью
PyInstaller, а затем упаковывается в установщик Inno Setup. В дистрибутив входят
интерпретатор Python, PyQt6, CPU-версия PyTorch, XGBoost, выбранные модели и
исходные датасеты для повторного обучения.

## Готовое приложение

Локальный установщик создаётся по пути:

`dist\installer\PredictiveQueryOptimization-Setup-0.8.37.exe`

SHA-256 конкретного установщика проверяется после сборки:

```powershell
Get-FileHash dist\installer\PredictiveQueryOptimization-Setup-0.8.37.exe -Algorithm SHA256
```

Версия 0.8.24 включает признаки потоков агрегации/сортировки/окон для новой
XGBoost, индексную историю проб, сочетания переписываний и выбор вариантов.
В 0.8.26 добавлены вкладка «Транзакции», локальный разбор и отдельный запрос
оценочных планов без запуска команд. Это ещё не оптимизатор всей транзакции.
В 0.8.27 добавлен общий каталог индексных кандидатов и качественное влияние
на операции записи, без DDL и выполнения команд транзакции.
В 0.8.28 появилась отдельная явная проба одного индекса на подтверждённой копии:
реальные SELECT, временный индекс и откат. DML транзакции не исполняется.
В 0.8.29 результаты отдельных проб отображаются в карточках/строках кандидатов;
поиск в DML отделён от SELECT, кандидат только для DML не запускает пробу чтения.
В 0.8.30 доступно сравнение до трёх отмеченных кандидатов поодиночке и попарно
с заданными числами повторений SELECT. Опт-ин проверка установленного EXE:
`--transaction-comparison-smoke-test` (требует отдельной копии и явного opt-in).
В 0.8.31 добавлены явные типы/значения позиционных параметров по командам,
локальный просмотр SQL со значениями и сброс устаревших результатов.
Проверка `--transaction-parameters-smoke-test` также требует отдельной копии
и opt-in; значения/текст исходного SQL в её успешный журнал не записываются.
В 0.8.32 добавлены повторные серии сравнения индексов, изменение порядка
вариантов и консервативная проверка устойчивости. Проверка
`--transaction-comparison-smoke-test` теперь выполняет две серии (шесть проб)
на копии и проверяет обе пары/все откаты; ускорение не является условием теста.
В 0.8.33 добавлен отдельный контроль нового SELECT-набора для зафиксированного
варианта. `--transaction-holdout-smoke-test` требует отдельной копии/opt-in и
проверяет реальный подбор → фиксацию → две контрольные серии, без DML.
В 0.8.34 добавлен локальный сценарий нагрузки записи. Режим
`--transaction-write-smoke-test` получает только планы/каталоги синтетической
университетской БД, не исполняет DML/DDL и не создаёт пробных индексов.
В 0.8.35 `--transaction-replay-smoke-test` — отдельный настоящий DML/COMMIT
на новых одноразовых копиях, только для известных синтетических БД и с явными
PQO_REPLAY_COPY_CONFIRMED=1, PQO_REPLAY_REFERENCE=pqo_university_index_lab.
Он проверяет queued worker, равенство состояний/результатов и удаление копий;
время и SELECT-only проверка не заменяют этот opt-in сценарий.
В 0.8.36 та же проверка выполняет две серии на шести свежих копиях плюс
закрытый снимок, проверяет смешанную оценку/таблицу эффекта и удаление семи БД.
Производительный выигрыш не требуется для успеха smoke: честный отказ из-за
дрейфа/регрессии также корректен. Положительный/отрицательные решения проверяются
отдельными детерминированными тестами, не подбором порогов под smoke-замеры.
В 0.8.37 добавлен отдельный `--transaction-select-rewrite-smoke-test`:
локальная queued-подготовка, два SELECT-редактора, затем вся транзакция с
заменой SELECT № 2 после UPDATE на шести свежих копиях. Нужны отдельные
PQO_SELECT_REWRITE_COPY_CONFIRMED=1 и
PQO_SELECT_REWRITE_REFERENCE=pqo_university_index_lab, известный синтетический
источник и только схема university. Проверяются результаты/итоговые данные,
отсутствие новых индексов, удаление семи БД и сохранность исходного редактора.
Сам SQL/значения в успешный журнал не записываются; положительный временной
выигрыш не является обязательным условием этой технической проверки.
Отдельный `--startup-smoke-test` открывает обычное окно, прогревает модели
и наблюдает event loop 20 секунд, без запросов. Для Windows-проверки нужен
`QT_QPA_PLATFORM=windows`: offscreen не воспроизводит нативные COM-события.
В 0.8.34 обработчик нативных исключений Windows сохраняет только текущий
поток: обход меняющихся стеков фонового импорта в CPython 3.13.3 приводил
к вторичному access violation при обрабатываемом исключении COM. Python/Qt
журналы остаются включены; остальные ОС сохраняют прежний all_threads режим.
При выборе новых весов нельзя оставлять старый установленный EXE: ошибка
`Prediction features are missing` означает несовместимость контракта, а не
необходимость добавить отсутствующие признаки нулями или переобучить модель.

Стандартный каталог установки:

`%LOCALAPPDATA%\Programs\PredictiveQueryOptimization`

Установщик создаёт ярлыки в меню «Пуск» и, если выбран соответствующий пункт,
на рабочем столе. Удалить приложение можно штатно через параметры Windows или
файл `unins000.exe` в каталоге установки.

Само приложение автономно, но для анализа SQL ему нужен доступный PostgreSQL.
Учебную БД проекта можно запустить командой:

```powershell
docker compose up -d --wait
```

## Воспроизводимая сборка

Требуются Windows 10/11, Python с созданным `.venv` и Inno Setup 6. Полная
команда:

Релизная сборка проверяется на Python 3.13.3. Для обычного запуска
исходников допустимы версии из диапазона `requires-python`, но релизную
Windows-сборку следует выполнять на 3.13.3: на тестовой системе Python 3.13.15
зависал в системном WMI-вызове ещё до запуска приложения.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

Скрипт устанавливает группы зависимостей `desktop` и `build`, генерирует
иконку, собирает каталог `dist\PredictiveQueryOptimization`, запускает
smoke-тест и формирует установщик. Smoke-тест проверяет не только запуск Qt, но
и реальную десериализацию артефактов XGBoost, DQN и селектора стратегии. Его журнал находится в
`%LOCALAPPDATA%\PredictiveQueryOptimization\artifacts\smoke-test.log`.

Если Windows сообщает `An Application Control policy has blocked this file`,
не отключайте системную защиту ради запуска неподписанной сборки. Исходный режим
можно проверить командой `python -m pqo.desktop --smoke-test`, а для выпуска
автономного EXE потребуется доверенная подпись кода или разрешение администратора
на запуск локально собранного приложения.

Для повторной сборки без установки зависимостей:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1 `
  -SkipDependencyInstall
```

Для быстрой повторной сборки с сохранением кэша PyInstaller добавьте
`-Incremental`. Перед финальной публикацией всё равно следует выполнить полную
сборку без этого флага.

Дополнительная явная проверка вкладки транзакций в собранном/установленном EXE:

```powershell
$env:QT_QPA_PLATFORM='offscreen'
$env:PQO_APP_DATA_ROOT="$PWD\artifacts\transaction-frozen-check"
.\dist\PredictiveQueryOptimization\PredictiveQueryOptimization.exe --transaction-smoke-test
```

Она использует текущее подключение приложения и упакованный пример
`examples/transactions/university-inspection.sql`: нужна тестовая БД со схемой
university. Можно задать свой файл через `PQO_SMOKE_SQL_FILE`. Получаются только
EXPLAIN-планы; исходные команды не выполняются, история/калибровка не пополняются.
С 0.8.27 также читаются системные каталоги и проверяется отображение индексных
кандидатов и предупреждений о записи. Индексы не создаются.
Результат — `artifacts/transaction-smoke-test.log` внутри `PQO_APP_DATA_ROOT`.

Проверка фактической пробы — отдельный opt-in, не часть обычного smoke-теста:

```powershell
$env:QT_QPA_PLATFORM='offscreen'
$env:PQO_APP_DATA_ROOT="$PWD\artifacts\transaction-trial-frozen-check"
$env:PQO_TRIAL_COPY_DATABASE='pqo_university_index_lab'
$env:PQO_TRIAL_COPY_CONFIRMED='1'
.\dist\PredictiveQueryOptimization\PredictiveQueryOptimization.exe --transaction-trial-smoke-test
```

Нужны исходная университетская БД в текущих настройках приложения и заранее
подготовленная отдельная копия. Этот режим действительно создаёт и откатывает
один индекс на копии и выполняет SELECT. Без явного подтверждения и имени другой
БД проба не запускается. Журнал — `artifacts/transaction-trial-smoke-test.log`
внутри заданного `PQO_APP_DATA_ROOT`. Порядок подготовки копии — в
[описании пробы](transaction-index-trials.md).

Чтобы получить только каталог приложения без установщика, добавьте
`-SkipInstaller`. Скрипт в конце печатает SHA-256 собранных исполняемых файлов.

Пользовательские результаты обучения и экспорта сохраняются отдельно от
неизменяемых ресурсов приложения:

`%LOCALAPPDATA%\PredictiveQueryOptimization\artifacts`
