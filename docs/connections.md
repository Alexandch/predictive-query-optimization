# Подключения к PostgreSQL

У приложения два независимых подключения:

- исследуемая БД — SQL, оценочные планы, прогноз и фактические проверки;
- служебная БД — схема `pqo`, история и решения по рекомендациям разных источников.

Они могут находиться на разных серверах. В исследуемую БД не нужно устанавливать
служебные объекты. Профиль содержит адрес сервера, роль, схемы и SSL-параметры;
пароль используется только в памяти текущего процесса.

## Добавление источника

1. Откройте «Настройки» → «Добавить подключение» и задайте имя профиля.
2. Укажите хост, порт, существующую БД и роль, введите пароль.
3. Настройте SSL. `require` требует шифрование; `verify-full` также проверяет
   доверенный сертификат и имя сервера. Для него укажите корневой сертификат CA.
4. Нажмите «Подключиться и загрузить схемы», отметьте нужные схемы и сохраните.
5. Используйте квалифицированные имена таблиц, например `sales.orders`.

`public` — одна схема, а не все схемы сервера. Анализатор принимает имена схем
из латинских букв, цифр и `_`, начинающиеся с буквы или `_`. Выбор схем ограничивает
область анализа и не заменяет права PostgreSQL.

Профили переключаются верхним списком БД. Смена источника сбрасывает планы,
результаты и доступность применения старых рекомендаций; исходный SQL остаётся
в редакторе. Во время фоновой операции переключение недоступно.

Для удалённого сервера должны быть настроены сеть, порт, `pg_hba.conf` и
сертификаты. Поддерживается PostgreSQL; драйверы других СУБД не реализованы.

## Служебная БД

В блоке «Служебная БД» задайте отдельные параметры, например БД `pqo_service`.

- «Проверить служебную БД» проверяет подключение и наличие схемы.
- «Создать служебную БД» создаёт пустую БД через `postgres`: нужны `CREATEDB`
  и доступ к административной БД. Существующая БД не заменяется.
- «Подготовить служебную схему» применяет только миграции `pqo`, без предметных
  схем и демонстрационных данных. Нужны DDL-права в служебной БД.

Администратор может подготовить хранилище заранее и выдать приложению права
чтения/записи истории. Получение схем и быстрый прогноз сами миграции не запускают.
Если служебная БД недоступна, готовый анализ остаётся на экране с сообщением об
ошибке сохранения; история автоматически не переносится в исследуемую БД.

## Права для проверок

Для прогноза нужны `CONNECT`, `USAGE` на схемы и `SELECT` на таблицы.
Проверка переписывания выполняет запросы в read-only транзакции. Индексные пробы
дополнительно требуют права создания индексов и места для них. Запуск DML на
одноразовых копиях требует `CREATEDB`, доступа к эталону и явного подтверждения.
Полный контракт приведён в [руководстве по транзакциям](transactions.md).

## Переменные окружения и профили

CLI использует `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`,
`POSTGRES_PASSWORD`, `POSTGRES_CONNECT_TIMEOUT`, `POSTGRES_STATEMENT_TIMEOUT_MS`,
`POSTGRES_SSLMODE`, `POSTGRES_SSLROOTCERT` и `PQO_ALLOWED_SCHEMAS`.
Значения по умолчанию определены в [config.py](../src/pqo/config.py).

У CLI со сбором данных сохраняется режим одного подключения: проверьте целевую
БД перед командой, записывающей историю или создающей пробные объекты.
Профили GUI не подставляются в CLI автоматически.

`PQO_SETTINGS_FILE` задаёт абсолютный путь к отдельному INI для изолированных
проверок. Без него Windows-приложение использует прежнее хранилище QSettings.
`PQO_APP_DATA_ROOT` меняет каталог локальных журналов, но не настройки подключения.
Пример проверки нового профиля — в [testing.md](testing.md).
