# Первый эксперимент обучения эффективности переписываний

Дата: 23.10.2026. Отдельная модель-кандидат, не новая модель времени выполнения
и не активный ранжировщик в приложении. Установленная версия остаётся 0.8.23.

## Данные и протокол

Использованы реальные numeric single-column FK из пяти схем учебной БД:
`aviation`, `retail`, `logistics`, `pagila`, `chbenchmark`. Явный флаг
`--all-relationships` расширил пакет до 69 связей, по девять известных шаблонов
на каждую: 621 пара SQL. Это перенос известных преобразований на другие связи
таблиц, не 621 произвольный бизнес-запрос.

Итоговый пакет: `artifacts/rewrite-batches/expanded-clean-20261023`.
Предварительный `expanded-20261023` в обучение не включён: часть его замеров
могла пересекаться с интеграционными тестами БД. Итоговый пакет собирался
отдельно, без параллельных тестов. Тесты запускались после завершения сбора.

На каждый вариант: read-only REPEATABLE READ, EXCEPT ALL, по одному прогреву,
три парных замера с чередованием порядка. Statement timeout 1500 мс, бюджет
проверяется между случаями; максимум 500 случаев за сеанс. Продолжение завершило
оставшуюся часть списка. В процессе выявлена временная Windows-блокировка
состояния читателем; атомарное сохранение теперь повторяет замену до четырёх
раз. Уже завершённые проверки не пересчитывались.

Аудит подтвердил 621 технически пригодную пару без исключений. Манифест фиксирует
450 development-строк из 50 семейств и 171 control-строку из 19 семейств.
Связанные исходные/переписанные формы и все шаблоны одной FK-связи остаются
в одной роли. Предыдущие демонстрационные пакеты и smoke-тесты в обучение
не добавлялись. Хэш подготовленной выборки:

`8340ff567f507d92a5083f101a91156b122f897bff41ff80d09fe1bea96ec16f`

## Обучение

Фиксированный XGBRegressor: 120 деревьев, max_depth=3, learning_rate=0.04,
random_state=42, один поток. Параметры не подбирались по результатам этого
контроля. Цель — `log(Tисходный / Tвариант)`. Признаки включают разрешённые
оценочные поля EXPLAIN, структуру обоих AST и ID правила. Фактическое время,
решение «принят/отклонён» и actual-поля не попадают в признаки.

Суммарный вес каждого семейства равен единице. Сравнения — константная медиана
development и отдельная медиана development для каждого правила. Контроль
не используется в fit или вычислении этих базовых оценок.

## Результат

MAE в логарифмической шкале ускорения, не в миллисекундах:

| Метод | Контрольный MAE |
| --- | ---: |
| Константная оценка | 0,87543 |
| Медиана по правилу | 0,76001 |
| XGBoost-кандидат | 0,34862 |

Снижение MAE относительно оценки по правилам — около 54,1%. Это не означает
ошибку прогноза времени в 0,35 мс или «точность 54%».

Bootstrap по целым семействам (1000 выборок, seed=42), 95%-й интервал разности
MAE модели и оценки по правилам: [-0,70157; -0,19773]; относительно константы:
[-0,82184; -0,31018]. Обе верхние границы отрицательные; диагностический
`passes_quality_gate=true` для данного фиксированного эксперимента.

При отборе предсказанного относительного ускорения не менее 5% выбрано 109
контрольных вариантов; 76,1% из них действительно достигли относительного
выигрыша 5%. Это precision только такого отбора, не общая «точность модели»
и не гарантия экономии 2 мс. Среди 171 контрольного исходного SQL 92 выполнялись
быстрее 1 мс: на них относительное время чувствительно к шуму.

Не все правила улучшились: для range-to-between MAE модели 0,10263 против
0,06430 у оценки по правилу; HAVING почти без разницы. По итогам этого контроля
не вводились отдельные поправки для правил и не менялись параметры модели.
Подробные per-rule значения сохранены в отчёте.

## Артефакты и воспроизведение

- `artifacts/rewrite-batches/expanded-clean-20261023/batch.json` — список и протокол.
- `artifacts/rewrite-batches/expanded-clean-20261023/split.json` — фиксированные роли.
- `artifacts/rewrite-batches/expanded-clean-20261023/journal` — полные доказательства опытов.
- `artifacts/rewrite-batches/expanded-clean-20261023/learning-report.json` — аудит и метрики.
- `artifacts/rewrite-learning/expanded-experiment-20261023/candidate.joblib` — модель-кандидат,
  векторизатор, версия признаков и происхождение выборки.

Повторное обучение с тем же журналом возможно в **новые** выходные пути:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pqo.rewrite_learning --directory artifacts/rewrite-batches/expanded-clean-20261023/journal --manifest artifacts/rewrite-batches/expanded-clean-20261023/split.json --report artifacts/rewrite-learning/reproduction-report.json --train-output artifacts/rewrite-learning/reproduction
```

Артефакты находятся локально и игнорируются Git. Этот документ сохраняет
агрегированные результаты, а не исходный пользовательский SQL. Модели из
`models/xgboost` и DQN не заменялись; автоматической активации нет.

## Что это пока не доказывает

Контроль отделён по связям таблиц, но использует те же девять шаблонов и те же
пять схем. Это не тест на полностью новой БД, не контроль новых правил и
не проверка оконных/произвольных аналитических запросов.

В каждом запросе пакета проверялся один основной вариант. Поэтому
`validated_ranker=false`: для подключения ранжирования ещё требуется отдельная,
заранее отложенная выборка запросов с несколькими кандидатами на один SQL и
проверка качества выбора при ограниченном бюджете измерений. Дополнительный
контроль не следует смешивать с обучением после просмотра его результатов.
EXCEPT ALL и реальные пороги остаются обязательными перед применением SQL,
независимо от положительного модельного балла.
