# Десктопное PyQt6-приложение

Приложение объединяет прогноз XGBoost, селектор стратегии оптимизации, быструю
однократную рекомендацию DQN и измеренный последовательный план индексов.
Обычная кнопка «Анализировать» не
выполняет пользовательский SQL: используется оценочный `EXPLAIN` без `ANALYZE`.

## Запуск

Если Windows-установщик уже выполнен, используйте ярлык
«Predictive Query Optimization» на рабочем столе или в меню «Пуск».
Установленная программа находится в
`%LOCALAPPDATA%\Programs\PredictiveQueryOptimization` и не требует отдельной
установки Python. PostgreSQL можно запустить из каталога проекта:

```powershell
docker compose up -d --wait
```

Запуск непосредственно из исходного кода нужен только для разработки:

```powershell
docker compose up -d --wait
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[desktop]"
.\.venv\Scripts\pqo-desktop.exe
```

По умолчанию используются PostgreSQL на `localhost:55432` и выбранные модели
из каталога `models`. Параметры можно изменить на вкладке «Настройки».
Пароль PostgreSQL не записывается в `QSettings` и существует только в памяти
текущего процесса.

Для подключения другой PostgreSQL укажите её хост, порт, имя БД, пользователя,
пароль и список разрешённых схем. Запросы лучше задавать с именем схемы,
например `sales.orders`; для таблиц без явной схемы анализатор использует
`public`. Пользователю БД нужны `CONNECT`, `USAGE` на схемы и `SELECT` на
анализируемые таблицы. Для обычного анализа право `CREATE` не требуется.

Кнопка «Глубокий анализ индексов» работает иначе и всегда показывает отдельное
подтверждение. Она реально выполняет SELECT через `EXPLAIN ANALYZE`, временно
создаёт до двух выбранных индексов и измеряет результат. Для неё пользователь
должен иметь право `CREATE` в целевой схеме. Весь эпизод выполняется в одной
транзакции и безусловно откатывается: приложение выводит проверенные DDL, но не
оставляет индексы в БД. Кандидат показывается только если PostgreSQL использовал
его в плане, измеренная награда положительна, а абсолютная экономия составляет
не менее 5 мс. Если фактическое исходное время ниже установленного порога
рекомендации, индекс не предлагается. Лимит пробных индексов — 64 МиБ.

Кнопка «Проверить переписывание SQL» формирует консервативные варианты без
изменения схемы: заменяет положительную проверку `COUNT(*)` на `EXISTS`, цепочку
равенств `OR` по одному столбцу на `IN` и две включительные границы на
`BETWEEN`. Исходный и новый запросы выполняются в транзакции `READ ONLY`.
Приложение сначала доказывает совпадение мультимножеств строк в обе стороны
через `EXCEPT ALL`, затем чередует измерения `EXPLAIN ANALYZE`. Новый SQL
показывается только при экономии не менее 5 мс и 5%; автоматически он не
применяется.

После обычного анализа селектор показывает один из трёх вариантов: ничего не
менять, проверить индекс или проверить переписывание SQL. Рядом выводятся
вероятности всех классов. Это навигационная ML-подсказка: она не создаёт индекс
и не подменяет SQL. Пользователь подтверждает её одной из двух кнопок глубокого
анализа, после чего PostgreSQL проверяет фактический выигрыш с полным откатом.
Ниже приложение выводит отдельный блок структурных рекомендаций по агрегациям,
JOIN, сортировкам и материализованным представлениям. Для каждого пункта указаны
основание, приоритет, действие и способ фактической проверки. Эти рекомендации
не изменяют SQL или схему автоматически.
При сохранении анализа ниже становятся доступны кнопки «Принять» и «Отклонить».
Для принятого пункта можно записать независимый замер времени до и после
оптимизации. Решение и результат сохраняются в служебной схеме `pqo`, видны в
истории и попадают в её CSV/JSON-экспорт.

Флажок «Сохранять в историю pqo» распространяется и на обычный, и на глубокий
анализ. Для глубокого анализа сохраняются фактические времена до/после,
измеренный выигрыш, причина остановки и каждый проверенный DDL с Q-оценкой и
reward. Если перед ним уже был сохранён обычный анализ того же SQL, результаты
связываются с одной записью запроса; иначе создаётся отдельная запись. Флажок по
умолчанию выключен, поэтому анализ чужой БД не требует служебных таблиц проекта.
Его следует включать только для БД, в которой установлена схема `pqo` из
`database/init`.

Для новой БД можно создать локальный калибровочный профиль. На вкладке
«Анализ» последовательно вставьте не менее десяти разных характерных SELECT и
нажмите «Добавить текущий SQL в калибровку». В отличие от обычного анализа эта
операция явно выполняет запрос через `EXPLAIN ANALYZE`, поэтому приложение
показывает подтверждение. После десяти разных SQL профиль становится готов, но
его применение нужно явно включить флажком. Поправка рассчитывается отдельно для
групп запросов; группе нужны минимум три разных SQL. Поправка применяется только
к уже встречавшемуся нормализованному шаблону, а для новой структуры остаётся
исходный прогноз модели. Под скорректированным результатом отображается базовый
прогноз.
Подробности и команды CLI приведены в
[руководстве по калибровке](database-calibration.md).

В установленной версии результаты обучения и экспорта записываются в
`%LOCALAPPDATA%\PredictiveQueryOptimization\artifacts`, поэтому программа не
пытается изменять защищённые файлы внутри своего каталога установки.

## Вкладки

- **Анализ** — ввод `SELECT`/`WITH`, быстрый прогноз без выполнения SQL и
  отдельные глубокие режимы с проверенным планом до двух индексов и измеренным
  переписыванием SQL. DDL и новый SQL только показываются и не применяются
  автоматически.
- **История** — последние 200 обычных и глубоких анализов из схемы `pqo`,
  включая фактическое время, измеренный выигрыш и проверенные индексы.
- **Эксперименты** — карточки parameter/stress-метрик, включая независимый
  logistics-контроль DQN, график
  «факт → прогноз» XGBoost и сравнение DQN с Random/NOOP. При пересчёте
  модель применяется к 3 398 агрегированным точкам текущего датасета.
- **Настройки** — подключение к PostgreSQL, разрешённые схемы, пути к XGBoost,
  однократной и последовательной DQN, селектору стратегии и проверка связи.
- **Обучение** — повторное обучение XGBoost или DQN на указанном датасете с
  выводом итоговых метрик. Для DQN доступны parameter и unseen-template
  stress-режимы. Во время работы отображается индикатор прогресса.

## Контроль качества модели

Обученный артефакт сначала сохраняется как кандидат в `artifacts/models`.
Кнопка назначения основной моделью активируется только если:

- у XGBoost не ухудшились `R²` и `MAE` в parameter- и stress-оценках;
- у DQN не снизилась accuracy и не вырос regret в parameter-оценке;
- DQN-кандид был обучен в parameter-режиме, а не тольо stress.

Перед заменой текущие файлы копируются в подкаталог `previous`.

## Экспорт

Историю анализа и экспериментальные результаты можно сохранить в UTF-8
JSON или в CSV с BOM для корректного открытия в Excel. JSON истории содержит
структурированные шаги глубокого анализа, а в CSV они записываются одной JSON-
ячейкой. CSV-экспорт эксперимента создаёт файл точек и соседний
`*_summary.csv` со сводными метриками.

Анализ, доступ к истории, проверка связи и обучение выполняются в фоновых
потоках, поэтому окно не зависает во время долгих операций.

Те же проверки переписывания доступны из командной строки:

```powershell
.\.venv\Scripts\pqo-rewrite.exe `
  "SELECT ... WHERE (SELECT COUNT(*) FROM ...) > 0"
```

Для просмотра синтаксических кандидатов без подключения к PostgreSQL добавьте
`--generate-only`.
