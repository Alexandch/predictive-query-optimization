# Десктопное PyQt6-приложение

Приложение объединяет прогноз XGBoost и рекомендацию DQN в одном
локальном интерфейсе. Пользовательский SQL не выполняется: для анализа
используется оценочный `EXPLAIN` без `ANALYZE`.

## Запуск

```powershell
docker compose up -d --wait
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[desktop]"
.\.venv\Scripts\pqo-desktop.exe
```

По умолчанию используются PostgreSQL на `localhost:55432` и выбранные модели
из каталога `models`. Параметры можно изменить на вкладке «Настройки».
Пароль PostgreSQL не записывается в `QSettings` и существует только в памяти
текущего процесса.

## Вкладки

- **Анализ** — ввод `SELECT`/`WITH`, прогноз времени, показатели плана и
  безопасная индексная рекомендация. DDL только показывается, но не
  применяется автоматически.
- **История** — последние 200 анализов из схемы `pqo`.
- **Эксперименты** — карточки parameter/stress-метрик, график
  «факт → прогноз» XGBoost и сравнение DQN с Random/NOOP. При пересчёте
  модель применяется ко всем 3 398 уникальным SQL из текущего датасета.
- **Настройки** — подключение к PostgreSQL, пути к XGBoost/DQN и проверка связи.
- **Обучение** — повторное обучение XGBoost или DQN на указанном датасете с
  выводом итоговых метрик. Для DQN доступны parameter и unseen-template
  stress-режимы. Во время работы отображается индикатор прогресса.

## Контроль качества модели

Обученный артефакт сначала сохраняется как кандидат в `artifacts/models`.
Кнопка назначения основной моделью активируется только если:

- у XGBoost не ухудшились `R²` и `MAE` в parameter- и stress-оценках;
- у DQN не снизилась accuracy и не вырос regret в parameter-оценке;
- DQN-кандид был обучен в parameter-режиме, а не тольо stress.

Перед заменой текущие файлы копируются в подкаталог `previous`.

## Экспорт

Историю анализа и экспериментальные результаты можно сохранить в UTF-8
JSON или в CSV с BOM для корректного открытия в Excel. CSV-экспорт эксперимента
создаёт файл точек и соседний `*_summary.csv` со сводными метриками.

Анализ, доступ к истории, проверка связи и обучение выполняются в фоновых
потоках, поэтому окно не зависает во время долгих операций.
