# Проверка калибровки на непересекающихся SQL

## Методика

Для ретроспективного development-эксперимента использованы 171 уникальный SQL и
30 production-like шаблонов из `production_control.csv`. Точные SQL в
calibration и holdout не пересекаются. Набор уже применялся в предыдущих циклах
разработки, поэтому результат не объявляется новым финальным контролем.

Проверены два разбиения с seed `1701` и долей калибровки `20%`:

- `parameter`: каждый шаблон представлен разными SQL в обеих частях;
- `unseen-template`: шесть целых шаблонов отданы калибровке, остальные 24
  присутствуют только в holdout.

Первый вариант использовал один глобальный коэффициент. Новый вариант разделяет
наблюдения по структуре SQL и диапазону базового прогноза, требует минимум три
разных SQL в группе и стягивает групповой коэффициент к `1,0`. Для неизвестной
или малочисленной группы применяется исходный прогноз без коррекции.

## Результаты

| Разбиение | Calibration / holdout SQL | Активных групп | Базовый MAE | Новый MAE | Базовый RMSE | Новый RMSE |
|---|---:|---:|---:|---:|---:|---:|
| parameter | 38 / 133 | 6 | 580,63 мс | **536,47 мс** | 1277,57 мс | **1245,94 мс** |
| unseen-template | 23 / 148 | 4 | 400,08 мс | **384,71 мс** | 777,97 мс | **732,06 мс** |

В parameter-режиме MAE снизилась на `7,61%`, RMSE — на `2,48%`, R² вырос с
`0,4453` до `0,4724`. В unseen-template MAE снизилась на `3,84%`, RMSE — на
`5,90%`, R² вырос с `0,5785` до `0,6268`. Доля прогнозов в пределах 20% при этом
немного снизилась, поэтому результат остаётся смешанным и требует независимого
финального контроля. В сравнении с глобальной поправкой устранено ухудшение MAE
на неизвестных шаблонах (`46,34%`).

## Продуктовое решение

- минимальный размер профиля увеличен с 3 до 10 разных SQL;
- для одной условной группы нужны минимум 3 разных SQL;
- при недостатке данных используется исходный прогноз, а не общий коэффициент;
- малые группы получают ослабленную поправку за счёт shrinkage к `1,0`;
- применение калибровки в PyQt по умолчанию выключено;
- пользователь включает профиль явно после сбора разнообразных запросов;
- `pqo-calibrate experiment` создаёт JSON-метрики, профиль и CSV с прогнозами;
- режим `unseen-template` сохраняется как обязательный стресс-тест.

Воспроизведение:

```powershell
.\.venv\Scripts\pqo-calibrate.exe experiment `
  dataset\postgresql\production_control.csv `
  models\xgboost\xgboost_query_time.joblib `
  artifacts\calibration\production_parameter `
  --calibration-fraction 0.20 --seed 1701 --split-mode parameter

.\.venv\Scripts\pqo-calibrate.exe experiment `
  dataset\postgresql\production_control.csv `
  models\xgboost\xgboost_query_time.joblib `
  artifacts\calibration\production_unseen_template `
  --calibration-fraction 0.20 --seed 1701 --split-mode unseen-template
```
