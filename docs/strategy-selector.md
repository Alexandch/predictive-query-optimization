# Выбор стратегии оптимизации

В проект добавлен отдельный верхнеуровневый классификатор, который выбирает один
из трёх вариантов: `NOOP`, `CREATE_INDEX` или `REWRITE_QUERY`. Он не заменяет DQN:
DQN по-прежнему выбирает конкретные индексы и их последовательность, а модуль
переписывания строит SQL, доказывает эквивалентность результата через `EXCEPT ALL`
в обе стороны и измеряет время в PostgreSQL.

## Формирование метки

Для каждого SQL выполняются транзакционные эксперименты с допустимыми индексами и
кандидатами переписывания. Индексы, уже покрытые существующей структурой, заранее
исключаются. Действие считается полезным, только если абсолютный выигрыш составляет
не менее 5 мс, относительная награда — не менее 0,05, а пробный индекс действительно
появился в плане. Для переписывания дополнительно обязательно равенство мультимножеств
строк. Если ни одно действие не прошло пороги, метка равна `NOOP`.

Схемы `logistics` и `chbenchmark` являются запечатанным контролем. Сборщик запрещает
использовать их и проверяет схемы физических таблиц каждого входного запроса до
соединения с PostgreSQL.

## Воспроизведение

```powershell
.\.venv\Scripts\pqo-strategy.exe seed-workload dataset\postgresql\strategy_workload.jsonl
.\.venv\Scripts\pqo-strategy.exe collect dataset\postgresql\strategy_workload.jsonl dataset\postgresql\strategy_experience.jsonl --actions-per-query 2 --repetitions 1 --resume
.\.venv\Scripts\pqo-strategy.exe summary dataset\postgresql\strategy_experience.jsonl
.\.venv\Scripts\pqo-strategy.exe train dataset\postgresql\strategy_experience.jsonl models\strategy
```

Сбор можно продолжать после остановки с параметром `--resume`. Одна строка JSONL
содержит SQL, неизменяемый контракт признаков, все измеренные исходы, пороги разметки
и итоговый класс.

## Первый baseline

Расширенный набор содержит 84 SQL-запроса и 58 шаблонов:

- `NOOP`: 28;
- `CREATE_INDEX`: 33;
- `REWRITE_QUERY`: 23.

На пяти разделениях по целым невидимым шаблонам средняя accuracy равна 0,703,
balanced accuracy — 0,711, macro-F1 — 0,697. Худшая balanced accuracy равна 0,622,
а средний выигрыш accuracy относительно majority-baseline — 0,316. Все заранее
заданные критерии пройдены, поэтому модель допущена к пробной интеграции в интерфейс.
Она показывает рекомендуемый класс и вероятности, но фактическое применение индекса
или переписывания по-прежнему требует транзакционной проверки специализированным
модулем.
