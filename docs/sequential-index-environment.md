# Последовательная multi-index среда

## Назначение

Одношаговая DQN выбирает только один индекс или `NOOP`. Новая среда моделирует
эпизод до трёх решений: агент может последовательно добавлять индексы разных
таблиц и завершить выбор явным действием `STOP`. Старое пространство действий и
модели `generic-v2`/`generic-v3` не изменены; для нового агента используется
кодирование `generic-v4-sequential`.

## Состояние

К обычному вектору SQL, плана и статистики добавлены семь признаков:

- доля уже использованных шагов;
- остаток бюджета хранения;
- накопленное ускорение относительно исходного плана;
- отношение текущего времени к исходному;
- доля оставшихся шагов;
- число ключевых колонок выбранных индексов;
- число выбранных `INCLUDE`-колонок.

Признак действия `is_stop` отличает завершение эпизода от создания индекса.
Ранее выбранные действия удаляются из доступного списка.

## Транзакционная безопасность

Эпизод выполняется под advisory-блокировкой в одной транзакции. Каждый индекс
создаётся типизированным `IndexAction`; произвольный DDL невозможен. При выходе
из контекстного менеджера транзакция откатывается целиком, включая все индексы.

Для секционированных таблиц бюджет учитывает сумму размеров родительского и
всех дочерних индексов через `pg_partition_tree`. Индекс, превышающий остаток
бюджета, откатывается к savepoint и получает отрицательную награду.

## Награда

Для принятого действия используется приращение ускорения относительно
исходного времени:

```text
reward = incremental_improvement
       - 0.05 * index_size / storage_budget
       - 0.01 * min(creation_time_ms / 1000, 1)
       - 0.01 * key_columns
       - 0.005 * include_columns
```

Перед исходным измерением выполняется прогрев. JSON-план разбирается по полям
`Index Name`. Если именно новый индекс не вошёл в план, его ускорение считается
нулевым: изменение времени из-за кэша не превращается в положительный reward.
Неиспользованный индекс всё равно расходует бюджет и получает штраф.

`STOP` имеет reward 0 и завершает эпизод. Превышение бюджета даёт reward −0,10.

## Формат опыта

Сборщик сохраняет для каждого состояния:

- терминальный переход `STOP`;
- одно действие поведения `CREATE`;
- текущие state/action-векторы;
- reward и параметры стоимости;
- следующее состояние;
- все допустимые признаки следующего действия;
- `done`, причину завершения и факт использования индекса.

Это позволяет следующему обучающему модулю использовать Bellman-target
`reward + gamma * max Q(next_state, next_action)`. Resume удаляет оборванный
эпизод и детерминированно собирает его заново.

## Пилотная проверка

Пилот на 12 запросах aviation, retail и Pagila сформировал 44 перехода в 23
состояниях. Создано 21 индексное действие: 10 новых индексов действительно
вошли в планы, 9 действий получили положительную и 12 отрицательную награду.
Размеры индексов находились в диапазоне от 16 КиБ до 30,9 МиБ. После сбора в
PostgreSQL осталось ноль временных индексов.

Пилот хранится в `artifacts/sequential/pilot_v3.jsonl`, SHA-256:
`35482F30A26F71DC8A9145296189A249ED4B201900FA5AED7A95113DFC1C195E`
(хеш будет отличаться при повторном измерении времени).

```powershell
  artifacts\sequential\aviation.jsonl --seed 731 --max-steps 2 --budget-mb 64

.\.venv\Scripts\pqo-sequential-collect.exe retail 100 `

.\.venv\Scripts\pqo-sequential-collect.exe pagila 100 `
  artifacts\sequential\pagila.jsonl --seed 733 --max-steps 2 --budget-mb 64
```

## Объединение и обучение

Каждый нетерминальный переход содержит `next_state_id`. Поэтому обучающий
модуль связывает только реально измеренные действия следующего состояния и не
делает Bellman-подстановку по непроверенным индексам. Эпизоды целиком попадают
в одну часть train/validation/test, что исключает утечку соседнего шага.

```powershell
.\.venv\Scripts\pqo-sequential-merge.exe `
  artifacts\sequential\multidomain_training.jsonl `
  artifacts\sequential\aviation_training.jsonl `
  artifacts\sequential\retail_training.jsonl `
  artifacts\sequential\pagila_training.jsonl

.\.venv\Scripts\pqo-sequential-train.exe `
  artifacts\sequential\multidomain_training.jsonl `
  artifacts\models\sequential_dqn `
  --epochs 1000 --ranking-weight 0.20 --seed 741
```

Первый многодоменный набор содержит 1 172 перехода, 279 уникальных эпизодов и
564 состояния. На независимой test-части калиброванная последовательная DQN
получила accuracy 78,01% и mean regret 0,0640. Стратегия «всегда STOP» получила
71,73% и 0,1228, случайная — 54,45% и 0,0851. Порог принятия CREATE равен
0,3872; он выбран только по validation-части и сохранён в артефакте модели.

Это development-оценка. Запечатанные `logistics` и CH-контроли при сборе,
калибровке порога и выборе эпохи не использовались.
