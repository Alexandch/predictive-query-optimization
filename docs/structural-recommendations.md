# Структурные рекомендации SQL

Обычный анализ приложения теперь дополняет XGBoost, DQN и переписывание SQL
детерминированными рекомендациями по четырём направлениям:

- агрегации;
- соединения `JOIN`;
- сортировки и пагинация;
- материализованные представления.

Этот слой не обучается на запечатанных контрольных БД и не выполняет DDL. Он
анализирует PostgreSQL AST и доступный `EXPLAIN (FORMAT JSON)`, поэтому каждая
рекомендация содержит наблюдаемое основание, предлагаемое действие и способ
проверки.

## Реализованные проверки

Агрегации:

- неагрегатные условия в `HAVING`, которые можно применить до `GROUP BY`;
- `COUNT/SUM DISTINCT` после большого соединения;
- `SELECT DISTINCT`, маскирующий размножение строк после `JOIN`;
- сброс hash-агрегации на диск по данным `EXPLAIN ANALYZE`.

Соединения:

- `CROSS JOIN` или другое соединение без `ON/USING`;
- функция либо `CAST` над ключом соединения;
- `LEFT JOIN`, который null-rejecting фильтр в `WHERE` фактически превращает в
  `INNER JOIN`;
- большой `Nested Loop` и многопартийный `Hash Join`.

Сортировки:

- большой `OFFSET`, для которого предлагается keyset-пагинация;
- `ORDER BY` во внутреннем запросе без `LIMIT`;
- дисковый `Sort` по фактическому плану.

Материализованное представление предлагается только для дорогой сводной
агрегации нескольких таблиц. Если запрос содержит изменяемый `WHERE`, готовый
DDL намеренно не формируется: сначала нужно обобщить представление, оставив
параметрический фильтр во внешнем запросе. Даже готовый шаблон создаётся с
`WITH NO DATA` и никогда не применяется приложением автоматически.

## Командная строка

Оценочный план без выполнения SQL:

```powershell
.\.venv\Scripts\pqo-structure.exe "SELECT ..."
```

Только синтаксические проверки без подключения к PostgreSQL:

```powershell
.\.venv\Scripts\pqo-structure.exe --sql-only "SELECT ..."
```

Фактический план для обнаружения сбросов на диск:

```powershell
.\.venv\Scripts\pqo-structure.exe --analyze "SELECT ..."
```

Последний режим действительно выполняет read-only запрос через
`EXPLAIN (ANALYZE, BUFFERS)` и предназначен для осознанной глубокой проверки.

## Обратная связь и фактический эффект

Если включён флажок «Сохранять в историю pqo», каждая структурная рекомендация
получает постоянный идентификатор. В приложении её можно явно принять или
отклонить и оставить комментарий. Это решение только сохраняется для анализа:
оно не переписывает запрос и не выполняет предложенный DDL.

Для принятой рекомендации можно внести независимые времена выполнения «до» и
«после». Приложение сохраняет относительный эффект и относит результат к одному
из классов:

- `improved` — ускорение больше 2% и больше 1 мс;
- `regressed` — такое же существенное ухудшение;
- `unchanged` — изменение находится в пределах допуска.

Записи видны в столбце «Структурная ОС» истории и входят в экспорт CSV/JSON.
Это формирует размеченный набор для будущей модели ранжирования рекомендаций.

Для существующего контейнера служебная таблица устанавливается один раз:

```powershell
Get-Content -Raw database\init\007_structural_feedback.sql |
  docker compose exec -T postgres psql -v ON_ERROR_STOP=1 `
    -U query_optimizer -d query_optimizer
```

В новом Docker volume файл применяется автоматически при первой инициализации.
