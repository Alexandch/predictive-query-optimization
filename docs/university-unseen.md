# Незнакомая БД: university

Создана 30.10.2026 отдельная PostgreSQL-база `pqo_university_unseen`, схема
`university`. Это синтетический университет, не внешний производственный набор:
40 000 студентов, 400 курсов, 2 000 потоков, 240 000 записей на курсы и
720 000 работ. Данные генерируются детерминированно. Вторичных индексов внешних
ключей при создании нет; PK присутствуют. Поэтому индексный пример специально
имеет потенциально полезную точку приложения, а не моделирует любую реальную БД.

Исходная `query_optimizer` не изменялась. В новой БД установлена пустая служебная
схема pqo для полноценной истории приложения. Синтетические фамилии/имена и
идентификаторы не содержат персональных данных реальных студентов.

## Подключение в приложении

Перезапустить приложение, открыть «Настройки» и изменить два поля:

- база данных: `pqo_university_unseen`;
- разрешённые схемы: `university`.

Сервер, порт, пользователь и пароль — те же, что у текущего локального
PostgreSQL (при стандартной установке localhost, порт 55432, пользователь
query_optimizer). Проверить подключение и сохранить настройки. Значения пароля
в этом документе и отчёте не сохраняются. Для возврата указать `query_optimizer`
и прежний список схем: `aviation,retail,logistics,chbenchmark,pagila`.
Настройки приложения автоматически не переключались.

SQL для ручной проверки:

- `examples/university-unseen/01-index.sql` — кандидат на индекс;
- `examples/university-unseen/02-rewrite.sql` — COUNT(*) > 0 → EXISTS;
- `examples/university-unseen/03-heavy-join.sql` — тяжёлый JOIN с агрегацией;
- `examples/university-unseen/04-window.sql` — CTE и оконное ранжирование.

Для индексного примера установить порог 5 мс, выигрыш 1 мс и 5%; стандартные
50 мс могут закономерно остановить короткий запрос. Предложение ускорения
тяжёлых запросов не гарантируется. Сначала запускать быстрый прогноз, затем
измерения, чтобы не спутать прогноз нового SQL с оценкой по предыдущим замерам.

## Первый прогон без калибровки

Использована модель, выбранная в приложении:
`models/xgboost/trial/xgboost_query_time.joblib`. Её SHA-256 записан в отчёте.
Все шесть прогнозов сохранены до любого фактического выполнения этих запросов;
калибровка отключена, измерения не добавлялись в профиль. Это новая схема и БД,
но не новые типы SQL-операторов, ранее неизвестные модели. Не следует называть
это доказательством обобщения на любые базы.

| Запрос | Прогноз, мс | Факт (медиана 3 замеров), мс |
|---|---:|---:|
| Поиск по первичному ключу | 1,856 | 0,079 |
| Фильтр студентов и сортировка | 4,113 | 2,861 |
| Записи одного студента | 12,112 | 16,281 |
| Коррелированный COUNT | 183,815 | 235,183 |
| JOIN четырёх таблиц и агрегация | 1678,987 | 1597,147 |
| Оконное ранжирование | 1086,023 | 875,627 |

На тяжёлом JOIN абсолютная относительная ошибка около 5,1%, на окне — около
24%. При этом короткий PK-поиск переоценён примерно в 23,5 раза: абсолютная
ошибка менее 2 мс не делает относительную точность хорошей. Не исключать этот
случай из отчёта ради красивой метрики. Факт измерен после прогрева; результат
зависит от кэша, нагрузки и ресурсов PostgreSQL.

Отдельная индексная проверка запроса записей студента: 12,642 → 0,056 мс,
принят индекс `(student_id) INCLUDE (enrollment_id, registered_at, status)`.
Переписывание COUNT → EXISTS: 260,530 → 66,947 мс, EXCEPT ALL подтвердил
совпадение мультимножеств на снимке. Это отдельные парные замеры, не числа
из таблицы прогнозов. После проверки пробных индексов нет, веса не изменены.
Цена INSERT/UPDATE/DELETE в этой проверке не измерялась.

Отчёт и все шесть SQL:
`artifacts/university-unseen-20261030/report.json`. Журнал переписывания
помечен `test`, в обучение не включается. Существующие контрольные модели
по этим результатам не подбирались и не дообучались.

## Воспроизведение

```powershell
# Только если БД ещё НЕ существует. Существующая база не перезаписывается.
.venv\Scripts\python.exe -m pqo.unseen_database create
# Нужен новый каталог отчёта. Созданная БД остаётся для ручной работы.
.venv\Scripts\python.exe -m pqo.unseen_database check --model models/xgboost/trial/xgboost_query_time.joblib --output artifacts/university-check-02
```

Команда create создаёт отдельную БД, таблицы и данные; команда check выполняет
только чтение и пробные индексы с откатом, не записывает калибровку и не обучает
модели. Запросы и параметры схемы после просмотра результатов первого прогона
не менялись. Новые результаты повторения не заменяют первый отчёт.
