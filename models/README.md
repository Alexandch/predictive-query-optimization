# Модели и результаты контроля

Назначение комплектных артефактов:

| Путь | Использование |
| --- | --- |
| `xgboost/trial/xgboost_query_time.joblib` | XGBoost plan-v1, выбор нового профиля GUI |
| `xgboost/xgboost_query_time.joblib` | сохранённая модель sql-v2 и совместимость прежних настроек |
| `xgboost/previous` | предыдущая версия XGBoost |
| `dqn/dqn_index_advisor.pt` | одиночное индексное действие, кодировка generic-v2 |
| `dqn/dqn_index_advisor.npz` | NumPy-экспорт той же DQN |
| `sequential_dqn/sequential_dqn_index_advisor.pt` | последовательные индексные шаги, generic-v4-sequential |
| `sequential_dqn/sequential_dqn_index_advisor.npz` | NumPy-экспорт последовательной модели |
| `strategy/strategy_selector.joblib` | предварительный выбор NOOP / индекс / переписывание |

Существующий профиль сохраняет свой выбор модели. Каталог `trial` содержит
комплектную plan-v1, но имя каталога само по себе не является подтверждением
качества на новой БД. Область её контроля — локальные aviation/retail;
обобщение на произвольный сервер не гарантируется.

XGBoost получает только доступные до выполнения признаки SQL, EXPLAIN и каталога.
Фактическое время не является входом прогноза. Калибровочный профиль хранится
отдельно и привязан к хешу весов.

## Метрики и происхождение

Рядом с весами находятся `metrics.json`, важности признаков и доступные manifest.
`xgboost/trial/trial-info.json` фиксирует происхождение plan-v1 и результаты её
допуска. Конкретные числа относятся к указанному набору и протоколу, а не ко
всем запросам приложения.

`control` содержит контрольные JSON/CSV: production-like, multidomain,
leave-one-database-out, negative_augmented, chbenchmark и sequential.
В них могут сравниваться исторические модели, не текущий выбор GUI.
`baseline`, `candidates`, `evaluation`, `final_experiment` сохраняют отдельные
артефакты сравнений; наличие файла не активирует его в приложении.

## Совместимость и замена

Имена и порядок признаков, преобразование цели и кодировка действий входят
в контракт модели. Отсутствующие признаки нельзя подменять нулями. Для DQN
экспорт NumPy должен соответствовать тем же весам, что и PT-артефакт.
В Windows глубокий анализ использует NumPy-инференс, PyTorch остаётся для обучения.

Кандидаты обучаются отдельно и оцениваются на отложенных данных до переключения.
Сохранённые прежние веса позволяют откатить выбор. Порядок описан в
[руководстве по обучению](../docs/training-guide.md), роли наборов — в
[описании данных](../dataset/postgresql/README.md).
Индексная Q-оценка и вероятность стратегии не заменяют фактическую проверку.
